当前分析与计划 · 07 SEP 2026 · 待确认建议

01 / 产品保持专注

借鉴 Watchboard 的专题组织方式，主界面仍然是一张地图和一列事件。地图、事件流、详情和时间筛选共同维护，不拆成互相同步的插件。

来源接入 → 原文留档 → 候选提取 → 地点校验与事件合并 → 地图 / 历史 / 发布

02 / 扩展放在真正会变化的地方

来源适配器、提取器、附加图层和发布渠道采用内置模块；地区、颜色、衰减窗口使用配置。首版不做第三方插件商店、不为每个模块建独立服务。

03 / n8n 是可选的外围工具

现有工作流能从数据库批量读取消息、调用模型筛选翻译、转发到 Telegram；不包含采集端。无关批次缺少状态回写、批次 ID 未消费、发送与回写存在重复窗口。它适合做接入实验，不能直接作为可靠的地图事件核心。

04 / 首版完整闭环

  1. 固定样本：验证地点、事件类型、时间和来源关系。
  2. 小范围采集：真实来源、未处理积压、断流与恢复。
  3. 地图与运营：事件详情、待定位、人工修正、历史查询。
  4. 输出闭环：同页截图、选定渠道发布、默认至少五分钟间隔。

未知地点不强行画点；多条报告不等于独立证实；历史查询采用最新修正，不冒充“还原当时已知事实”。自动发布使用独立保存的视图。

这份原型验证什么？

只验证布局、筛选、回看、地图与列表联动，以及扩展入口的分寸。全部事件沿用旧原型的合成数据；没有接入 Telegram、数据库或模型，也不会实际发送消息。审批、可靠恢复和自动发布仍属于后续工程实现。
